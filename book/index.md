# Tahmures

## The Art and Engineering of Speaking with Intelligent Machines

Language becomes powerful when it can transform hidden, chaotic, or
inaccessible knowledge into forms that can be recorded, examined, tested,
understood, and shared.

*Tahmures* is a practical book for working developers. It begins with prompts
as interfaces, then develops the requirements, context, evaluation, security,
and operational practices needed to build reliable language-model systems.
Python is the primary implementation language; Go provides a production-minded
second view. Every core experiment can run offline with synthetic fixtures.

!!! note "A note on the stories"

    This book draws creative inspiration from the legendary figure of Tahmures
    as represented in Iranian epic tradition. The chapter narratives are
    original fictional episodes created for teaching prompt engineering. They
    are not translations, adaptations, or reconstructed passages from
    Ferdowsi's *Shahnameh*.

## Begin the journey

Part I follows Tahmures from a confident commander to an investigator who
defines success, separates instruction from evidence, and tests examples
instead of trusting a single persuasive result.

[Start Part I](part-1/index.md)

Part II follows him from investigator to experimenter. He validates reusable
templates and structured outputs, builds observable workflows, separates
generation from selection, evaluates creative work with people, and constructs
bounded context deliberately.

[Continue to Part II](part-2/index.md)

Part III follows him from experimenter to system designer. He governs context,
retrieval, memory, tools, autonomous loops, and hand-offs so useful language
cannot silently acquire evidence, authority, or a life beyond the current
goal.

[Continue to Part III](part-3/index.md)

Part IV follows him from system designer to evaluator, operator, guardian, and
teacher. He builds anchored rubrics and regression gates, defends trust
boundaries, binds consequential authority, observes drift, and learns which
requirements must be enforced by mechanisms other than language.

[Complete Part IV](part-4/index.md)

## How to use the book

Each chapter moves through the same learning rhythm:

> narrative problem → engineering question → mental model → naive attempt →
> failure analysis → improved design → experiment → evaluation →
> implementation → limits

The technical chapter stands independently if you skip the tale. If you run the
labs, record a prediction before looking at the fixture results: the discipline
of being wrong in an observable way is one of the book's central tools.
